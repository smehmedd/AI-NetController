# Open-Source Local AI Bridge Architecture (Ollama & vLLM)

The CST Autonomous Host Agent interfaces directly with locally hosted LLM engines via the OpenAI-compatible HTTP API or native Ollama endpoint (`http://127.0.0.1:11434/api/generate`).

## Recommended Models & VRAM Requirements

1. **DeepSeek-R1 (Distill Qwen 32B / 14B / 8B / 1.5B)**
   - *32B (Q4_K_M)*: ~20GB VRAM (RTX 3090 / 4090 / A5000)
   - *14B (Q4_K_M)*: ~9.5GB VRAM (RTX 3060 12GB / 4070)
   - *8B (Q4_K_M)*: ~5.5GB VRAM (RTX 3050 / 2060 / 4060)
   - *Role*: Step-by-step chain-of-thought verification, reasoning about OS states and network anomalies.

2. **Qwen 2.5 Coder (32B / 14B / 7B)**
   - *7B (Q4_K_M)*: ~5.2GB VRAM (Very fast sub-15ms token latency)
   - *Role*: Precise PowerShell, Bash, and Python script generation.

3. **Llama 3.3 (70B Instruct)**
   - *Q4_K_M*: ~40GB VRAM (Dual 3090 / 4090)
   - *Role*: Central fleet coordinator for multi-node autonomous tasks.

## Security Isolation & Sandboxing
Every command generated by the local AI engine passes through:
1. **AST Lexer & Whitelist Filter**: Catches chaining (`&&`, `;`, `|`), piping, or privilege escalation tokens.
2. **Human-in-the-Loop (HITL) Gate**: Prompts the mobile client for operator approval before dispatching destructive commands (`rmdir`, `format`, `del /f`).
3. **Windows Job Object Sandbox**: Enforces a 256MB memory cap and process tree cleanup on exit (`KILL_ON_JOB_CLOSE`).
